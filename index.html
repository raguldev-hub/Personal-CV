VisionAttend

AI-powered face recognition attendance system

  • Built a three-tier system: a Python computer-vision pipeline, a Spring Boot REST backend and a React (Vite) dashboard.
  • Used OpenCV's YuNet and SFace models with cosine similarity to identify people from a live webcam feed, replacing a Haar Cascade + LBPH approach for higher accuracy.
  • Designed REST APIs with Spring Boot, JPA and MySQL that mark attendance idempotently and serve attendance lists.

Working flow · from webcam to dashboard

  1. Webcam feedLive video frames are read by the Python pipeline.
  2. Face detectionOpenCV YuNet finds each face in the frame.
  3. Face encodingSFace turns the face into an embedding vector.
  4. MatchingCosine similarity compares it with enrolled students.
  5. Spring Boot APIA REST call marks attendance, once per person (idempotent).
  6. MySQL + ReactJPA stores the record; the dashboard shows attendance lists.

FactGuard

AI-powered fake news detection system

  • Built a FastAPI backend with a two-stage Gemini AI pipeline (claim understanding, then an evidence-based verdict) that pulls live evidence from NewsAPI, GNews and CricketAPI.
  • Added a multi-engine OCR fallback (EasyOCR, Tesseract, PaddleOCR) and URL text extraction with trafilatura.
  • Built a fact-checking layer that computes a confidence score from source credibility and evidence overlap.

Working flow · from claim to verdict

  1. User inputA text claim, a screenshot or a news URL.
  2. Text extractionImages go through OCR (EasyOCR, Tesseract, PaddleOCR fallback); URLs through trafilatura.
  3. Gemini stage 1Understands the claim and what needs checking.
  4. Live evidenceFetched from NewsAPI, GNews and CricketAPI.
  5. Gemini stage 2Weighs the evidence and gives a verdict.
  6. Confidence scoreBuilt from source credibility and evidence overlap.

College Placement Portal

Full-stack campus recruitment system

  • Built a placement platform with JWT authentication and role-based access for Students, Companies and Admins.
  • Designed 34 REST APIs across a layered Spring Boot architecture (Controller → Service → Repository → Entity).
  • Built a server-side eligibility engine that checks CGPA, branch and backlog criteria before an application is allowed.

Working flow · every API request

  1. LoginStudent, Company or Admin signs in.
  2. JWT tokenSpring Security issues a token and checks it on each request.
  3. Role checkAccess is limited by role.
  4. ControllerReceives the request from one of the 34 REST APIs.
  5. ServiceApplies the business rules.
  6. Repository → MySQLReads and writes the Entity data.

Application flow · when a student applies

  1. Student appliesSubmits an application through the API.
  2. Eligibility engineThe server checks CGPA, branch and backlog criteria.
  3. DecisionEligible: the application goes through. Not eligible: it is blocked before saving.
